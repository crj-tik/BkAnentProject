# Spec Delta

## Purpose

为 Supervisor 提供基于真实统一能力目录的模型工具调用，使普通请求和显式技能请求都由模型理解需求、选择调用，并以相同的调用级边界处理权限、审批、结果回写、恢复和失败。

## ADDED Requirements

### Requirement: 两种请求共享模型理解与能力选择

未显式指定 skill 的新请求 SHALL 进入 AUTO，指定有效 skill 的新请求 SHALL 进入 EXPLICIT_SKILL；两者 MUST 使用相同的模型决策与工具执行语义。模型 SHALL 持续获得原始请求、相关上下文和实际工具结果，决定回答、补充信息、能力调用或结束。系统 MUST NOT 先通过关键词、默认领域、默认 Agent、默认 intent 或固定业务链决定调用目标；显式技能 MUST NOT 绕过模型对本次需求的理解。

#### Scenario: 含否定词的请求不被入口关键词分流
- **WHEN** 无 skill 的请求为“不要发送通知，只分析这份合同”
- **THEN** 平台不预先调用 notification Agent，实际调用来自模型有效输出，并受权限和审批约束

#### Scenario: 可以直接回答
- **WHEN** 模型认为问候请求无需外部能力并返回最终答案
- **THEN** A2A 与 MCP 调用记录均为空，任务正常完成

#### Scenario: 显式技能仍理解自然语言输入
- **WHEN** 用户指定找房和营销指引技能，并以自然语言提供预算、交通偏好和目标人群
- **THEN** 模型获得技能正文和原始需求，能够提取本次参数、处理缺失或冲突，再决定调用，不接收平台预选的业务计划

### Requirement: 模型获得可实际执行的统一能力目录

系统 SHALL 向模型提供当前已发现、有效且授权可见的 A2A/MCP/本地能力，每项包含稳定身份、无冲突模型名称、description 和输入 schema，并对应真实执行入口。A2A 描述 MUST 保留发布的描述、技能和能力事实，MCP MUST 保留实际工具 schema；目录 SHALL 在单轮内一致并支持后续轮次刷新。同一逻辑 Agent 的 endpoint 更新 MUST 更新实际调用目标，且保留已接受远端任务的关联。

#### Scenario: 动态新增领域不需要关键词配置或业务节点
- **WHEN** 一个新领域 Agent 已被成功发现且调用者有权限，其 description 和 schema 有效
- **THEN** 后续模型调用能够看到并委托该 Agent，无需新增关键词或该领域专用执行节点

#### Scenario: 两个 MCP 服务拥有同名工具
- **WHEN** 两个连接均声明工具名称 search 且调用者有权限
- **THEN** 两项能力以不同稳定身份可见并可准确调用，不静默覆盖

#### Scenario: Agent 地址发生变化
- **WHEN** 已注册的同一逻辑 Agent 更新了有效 endpoint
- **THEN** 新调用使用更新地址，不继续使用过期缓存；已接受的远端任务仍可按原调用关联续查

### Requirement: 模型提出调用而不隐式执行

Supervisor 的模型决策 MUST 只产生回答、技能加载、补充输入请求或业务工具调用，所有业务调用 MUST 经过统一治理后才执行，同一调用不得被模型适配与外层执行各执行一次。控制调用 MUST NOT 扩大业务能力范围，每轮最多一个且必须单独调用。技能加载成功后 SHALL 返回模型继续决策，不建立技能专属执行器或业务分流。模型同轮提出多个控制调用，或混合技能加载/补充输入与业务调用时，系统 MUST 拒绝整批调用，各 toolCallId 返回关联错误；不激活技能、不进入等待输入、不触发审批、不执行业务，下一轮由模型分轮重提。

#### Scenario: 模型提出需要审批的工具调用
- **WHEN** 模型输出一个需要审批的业务调用
- **THEN** 模型决策期间业务执行次数为零，只有完成有效审批后调用执行入口才能执行

#### Scenario: 同轮混合技能加载和业务调用
- **WHEN** 同一模型响应同时提出 skill 加载与 A2A 或 MCP 调用
- **THEN** 每项调用收到可关联的分轮错误结果，技能状态不变且业务副作用为零，后续轮次由模型重新提出调用

#### Scenario: 同轮混合补充输入和业务调用
- **WHEN** 同一模型响应同时请求补充输入并提出业务调用
- **THEN** 整批返回分轮错误，不执行该业务或进入等待输入，后续轮次由模型明确提出单独控制动作

#### Scenario: 同轮提出多个控制调用
- **WHEN** 模型同轮提出两个 skill 调用，或同时提出 skill 和补充输入控制调用
- **THEN** 每个 toolCallId 均返回未执行错误，原技能、等待和审批状态不变，模型在后续轮次逐个请求控制动作

### Requirement: 工具结果驱动后续模型决策

系统 SHALL 将实际执行结果按 toolCallId 返回模型，由模型决定下一步或结束。nextHints 和风险输出 SHALL 作为结果数据提供，MUST NOT 自动触发下游业务调用。并行调用 SHALL 来自模型同轮提出的独立调用，并受容量和预算约束；使用先前结果的后续调用 SHALL 由模型在获得结果后提出，系统 MUST NOT 从技能正文构建步骤依赖、业务顺序或完成条件检查。

#### Scenario: 建议不自动触发通知
- **WHEN** Subagent 返回 nextHints=[notification.send]
- **THEN** 平台将建议交给模型，未出现后续有效工具调用时不执行通知

#### Scenario: 模型获得找房结果后继续决策
- **WHEN** 找房调用完成并返回候选数据
- **THEN** 模型下一轮获得该实际结果，并决定是否调用对比能力；平台不自行生成对比调用

#### Scenario: 模型提出并行调用
- **WHEN** 模型同轮提出两项独立且有效的调用，容量和预算均允许
- **THEN** 两项调用可并行执行，各自保存调用身份和结果，不要求为对应领域增加分支节点

### Requirement: 补充输入具有明确等待与续接语义

模型 SHALL 通过结构化补充输入控制动作提出问题和缺失字段，系统 MUST 持久化 WAITING_USER_INPUT 和原模型上下文，不以问号或消息关键词决定等待。续接 SHALL 仅接受有权限的原任务 owner、处于等待输入的任务和可去重请求，并串行处理；有效续接 MUST 沿用原模式、session、技能快照、MCP 选项、请求授权上限及累计预算，并重新验证当前权限。不允许借新 skill 更换显式约束、新请求默认值扩大授权或重置已消耗预算。原授权上限 SHALL 表达请求政策，MUST NOT 被解释为冻结的 Agent 名单，AUTO 后续目录刷新仍按原政策与当前权限决定可见能力。未明确续接的请求 SHALL 作为新任务处理，审批回调 MUST NOT 兼任输入续接入口。

#### Scenario: 缺失参数后继续原任务
- **WHEN** 原任务等待输入，owner 以有效续接关联补充预算
- **THEN** 原模型上下文获得补充信息，在原模式和技能快照下继续决策，重复续接不会重复推进

#### Scenario: 新请求与显式续接分离
- **WHEN** 同会话用户发送未携带续接关联的新请求
- **THEN** 创建新任务，不因消息历史或问号继承原等待状态和显式技能

#### Scenario: 续接试图切换技能
- **WHEN** 一个等待输入的显式任务收到带有另一技能选择的续接
- **THEN** 明确拒绝策略更换，不覆盖原技能快照或按新技能继续

#### Scenario: 续接不能扩权或重置预算
- **WHEN** 原任务禁止 MCP 或已经消耗部分预算，owner 使用缺省选项续接
- **THEN** 原 MCP 禁用政策和累计预算保持生效，当前权限重新验证，缺省值不能扩大权限或恢复全部额度

#### Scenario: AUTO 续接后发现新 Agent
- **WHEN** 等待输入期间新 Agent 被发现，原请求政策与当前身份均允许调用该能力
- **THEN** 后续模型目录能够显示新能力，不因执行开始时的 Agent 名单冻结而将其排除

### Requirement: 调用治理与失败语义保持硬边界

每次 A2A/MCP/本地调用 MUST 验证目标、参数 schema、服务端身份、权限、有效技能范围、预算和适用审批策略。模型不得覆盖服务端身份或批准结果。需要审批的动作 SHALL 在执行前保存调用和参数并暂停，批准后仅恢复该动作；参数变化 MUST 重新审批。模型或能力不可用 SHALL 返回明确错误或等待状态，允许同模式有界重试；系统 MUST NOT 静默切换关键词路由、默认 listing 或另一业务目标。

#### Scenario: 审批批准后恢复
- **WHEN** 一个动作等待审批并获批准
- **THEN** 系统恢复原调用和已批准参数，不重新规划不同目标或执行未批准副作用

#### Scenario: 执行前能力失效
- **WHEN** 模型可见的能力在实际执行前下线或失去权限
- **THEN** 该调用明确失败或返回不可用结果，不利用旧快照越过校验

#### Scenario: 模型不可用
- **WHEN** 任一新模式的模型调用有界重试耗尽
- **THEN** 记录模型不可用错误，不发起通过关键词猜测的 A2A/MCP 请求

### Requirement: 调用事实与技能快照可恢复

系统 SHALL 持久化执行模式与版本、模型消息及 toolCallId、有效技能快照、调用目标与参数关联、状态、远端 Task、审批和产物，并支持查询及 SSE 关联。恢复 MUST 复用已完成结果，已接受远端任务 MUST 续查；副作用提交结果未知时 MUST 先对账或等待核对，不盲目重发。恢复 MUST NOT 根据技能正文推导步骤进度或自动补齐业务步骤，且不得对无远端幂等支持的调用承诺 exactly-once。

#### Scenario: 进程在结果持久化后重启
- **WHEN** 调用已完成并记录结果，但模型尚未处理该结果时进程重启
- **THEN** 恢复时复用原 toolCallId 和结果，模型继续决策而不重复该调用

#### Scenario: 已接受远端任务
- **WHEN** A2A 远端已经接受任务，而本地执行暂停或重启
- **THEN** 根据原调用关联继续查询远端 Task，不生成一个新的委托替代原调用

#### Scenario: 提交结果未知
- **WHEN** 有副作用的请求已发出但连接超时，远端是否执行无法确认
- **THEN** 记录结果未知状态并对账，不因 checkpoint 恢复自动再次执行

### Requirement: 各入口保持一致语义和版本兼容

Supervisor 同步与异步入口 SHALL 使用相同模式及能力选择语义，普通聊天兼容入口 SHALL 逐步接入同一核心并保留现有字段与 MCP 禁用选项。新任务 MUST 使用新模型循环，旧未完成任务 MUST 依据已记录的执行版本恢复；不能用新状态语义强行解释旧 checkpoint，或将新任务静默交给旧关键词 runner。

#### Scenario: 异步执行不改变选择权
- **WHEN** 相同无 skill 请求通过同步和异步入口提交
- **THEN** 两者均由模型选择能力，异步入口不会恢复旧关键词分流

#### Scenario: MCP 被请求禁用
- **WHEN** 请求的 MCP 禁用选项生效
- **THEN** MCP 不作为有效可调用能力，模型和 skill 均不能越过该限制

#### Scenario: 旧任务恢复
- **WHEN** 新部署加载升级前的未完成 checkpoint
- **THEN** 使用相容旧执行版本恢复，不用新模型循环解释旧计划状态
