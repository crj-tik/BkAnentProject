# 房源经营域合并设计

## Context

动机见 proposal.md。当前比较实现集中在 `CompareAnalysisServiceImpl`、`CompareReportCacheServiceImpl` 和 PDF 服务，使用与房源相同的 DTO；`ListingComparisonFacts` 已提供量纲换算及来源指纹。旧比较按 ID 调用已拒绝无凭据读取的 RPC，Studio 则已有受权读取桥，二者不能以放开旧 RPC 的方式统一（LR-54、KI-115）。

用户确认：业务数据目前模拟，房源以接口接入。当前源码仍以本地 `listing_info` 为主要数据模型，因此接口来源适配是本 change 的明确新增能力，不把现有数据库 CRUD 当作上游系统。现有测试包括 `ListingBusinessAuthorizationTest` 和两域技能装配测试；合并需迁移这些行为验证。

## Goals / Non-Goals

**Goals:** 在现有 `listing-master-service` 内统一授权快照、对比与报告；上游接口可由模拟实现替换，派生结果保留来源、版本和数据性质。

**Non-Goals:** 不建设客户 CRM、成交状态机或真实上游写入；不改 Supervisor 通用拓扑，不合并 Auth、Memory、RAG，不在本 change 实施知识或营销调整。

## Decisions

### 1. 保留房源模块名，比较成为内部业务包

将比较计算、报告存储/PDF及工具迁入房源模块的 `comparison` 包，保留 `listing-agent`，新增对比技能。相比继续保留两个对外 Agent，此方式减少同一组事实在两个身份间来回读取；相比同时重命名为新服务，保留模块名可缩小部署与身份变更范围。报告有自己的持久生命周期，但其事实来源仍归房源域。

### 2. 接口事实与本地维护记录分别持久化

定义 `ListingSourcePort`，提供有界搜索、批量详情和当前版本核验。首期提供显式 `fixture` 与 `http` 适配器；HTTP 地址/凭据来自受管配置，端点未配置时返回不可用，不回退 fixture。fixture 使用相同契约并标记 `SIMULATED`，测试可通过本地受控 HTTP 夹具覆盖映射。

输入固定包含 `sourceSystem/sourceId/sourceRevision/observedAt/dataMode`、事实字段及金额单位；无上游 revision 时用规范化投影 hash，不能用抓取时间冒充版本。新增稳定来源映射，旧 Long ID 保留在 `legacy-local` 来源下，外部字符串 ID 不截断或哈希成可能碰撞的旧 ID。DTO 兼容层显式映射身份。

来源模式由服务端适配器确认：已确认真实为 REAL、模拟为 SIMULATED、性质不明为 UNKNOWN；派生材料只有全部来源均为 REAL 才为 REAL，含未知来源为 UNKNOWN，已知真实/模拟混合为 MIXED。数据模式与指标是否可计算是不同字段，不以 UNKNOWN 来源替代具体指标缺口说明。

上游价格、可售状态等为外部事实，本地只维护资料补充、维护事项和受权投影。没有上游写接口时，完成本地待办只代表操作人提交了处理记录，不能宣称上游已调价或已核验。旧本地模式显式标识来源；既有 SQL 列表/详情和 RAG 索引职责继续保留，不把接口失败转换为另一路检索成功。

### 3. 比较只使用同次授权和量纲一致的快照

批量读后校验实际用户及每套来源范围，再计算客观指标；金额输入明确单位，旧万元字段只在边界换算一次。报告身份绑定来源引用、版本/hash、规则版本和模式。缺失字段显示未知，硬条件不能被模型解释覆盖。

生成、查看、分享、导出前都核验当前来源和读取权。来源改变时历史报告标为 `STALE`，可明确请求新报告；撤权时不返回旧正文/PDF；依赖故障返回结构化不可用。owner-only 报告索引和正文/文件校验替代裸 shareCode 读取；旧报告没有可信归属时拒绝访问并保留文件供受控核对。

### 4. 合并时保留历史执行和 Memory 身份

已接受的 compare 调用继续按原 descriptor/taskId 对账或排空，不创建 listing 替代任务；旧检查点仍只读。新请求使用 listing 身份及必需 Memory（LR-22/23/96）。历史 `compare/compare-agent` 数据不批量改名，也不因 owner 相同开放给 listing；确需引用时使用现有受权共享导出。先保留已登记只读历史能力，确认无在途依赖后再停旧实例，不提前撤销原验证公钥。

### 5. 对公开契约明确迁移

新增带来源版本和当前凭据的比较契约，更新 Studio 比较调用方及 Supervisor 技能的能力范围。旧 `/compare/**` 可转到房源服务内适配，但仍执行相同当前授权；缺少可信归属的旧分享返回明确退役结果。无凭据旧比较 RPC 不能作为新实现的读取路径。通用动态目录不增加关键词路由，新增技能不引入顺序检查器。

Auth 协议由其他会话维护；本域只提供资源引用与操作，使用其最终可信 principal/scope 适配器，缺少授权事实即拒绝。产品字段 brokerId、来源 ID 和报告 hash 均不授予权限。

## Risks / Trade-offs

- [上游字段和单位不同] → 规范输入独立于旧 DTO，适配器校验单位、必填身份和版本，拒绝模糊数据。
- [一次比较读取期间来源变化] → 结果冻结版本并在输出/使用前复核；不能取得可核验快照时明确失败。
- [旧报告没有 owner] → 保留原文件和迁移清单，默认拒绝共享，不按分享码或文件路径猜归属。
- [停 compare 导致任务丢关联] → 先清点并排空/对账，保留旧身份及部署回退制品；迁移回滚不重放业务调用。
- [模拟结果误当真实事实] → 数据模式从来源继承到报告/PDF/Agent 输出，不能由请求者改成 REAL。

## Migration Plan

1. 固化旧接口、调用方、报告卷、历史任务与 Memory 身份清单；为新增映射及报告元数据添加增量迁移和初始化清单。
2. 先上线房源内部比较及接口适配，使用 fixture 验证授权、版本、金额和旧数据映射，再按受管配置接上游 HTTP。
3. 更新调用方、Card/技能、MCP endpoint 和网关路由；停止 compare 新任务，按原身份完成排空或登记未知结果。
4. 验证没有新消费者和活动调用后，从 reactor/Compose/配置发布列表中退役独立比较部署；旧报告卷、历史记忆空间及账本保留。
5. 回退恢复原匹配版本和路由，新增表/映射继续保留；旧任务按原身份恢复，不执行“重新生成全部报告”补救。

## Open Questions

真实房源接口的受管地址、凭据、字段映射和速率额度由部署接入提供。规范契约、模拟验收和上述任务拆分不依赖这些具体值；其补齐仅决定真实 HTTP 适配的联机验收时点。
