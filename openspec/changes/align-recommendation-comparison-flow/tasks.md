## 1. 推荐与两套选择

- [ ] 1.1 发布推荐、创建两套对比、读取与重新生成动作及 Schema，解析并绑定共享条件和候选定义，复用共同 A2A 信封。
- [ ] 1.2 接入经纪人临时输入和建档买方运行态需求。复用统一的硬条件、软偏好分组及来源验证，保存推荐工件、排序与理由。
- [ ] 1.3 在真实 Studio 入口支持明确选择两套不同的合格房源，允许从推荐外的同条件筛选结果选择。验收重复身份、跨区域、超预算、指定房型不符、下架和选择后版本变化。

## 2. 历史报告读取

- [ ] 2.1 将历史快照授权、来源变化观察和新对比资格分别核验，允许获准旧报告在价格或状态变化后继续读取，保留真实撤权时的拒绝。
- [ ] 2.2 读取时返回 `CURRENT / CHANGED / UNVERIFIED` 及一条必要提醒，原卡片、表格和 PDF 按旧快照呈现。验收新旧事实不混写、来源暂不可核对、权限无法核实时的对应处理。
- [ ] 2.3 复用原卡片投影，覆盖存量 2–6 套报告和原 JSON，确保推荐理由使用推荐产物表达，卡片事实与确定性指标同源。

## 3. 重新生成与报告存储

- [ ] 3.1 显式重新生成时取当前事实及有效条件，保存新报告标识与前版引用，原版继续可读。把计算缓存与生成实例、操作去重关联起来。
- [ ] 3.2 原房源已下架时保留旧报告并提示无法重新生成，由经纪人另起一次对比。验收不创建成功的新报告、不自动替换原选择。
- [ ] 3.3 为磁盘元数据增加可兼容读取的生成标识、条件及前版关联，使用可恢复原子写入，验收中断重试、同操作复用、独立操作生成新实例和旧文件加载。

## 4. 入口与权限验收

- [ ] 4.1 使 Studio 对比工件关联 Listing 领域报告，保留工作区版本、事务和幂等回执，串通查看旧版和重新生成的真实入口。
- [ ] 4.2 依 KI-289 为 A2A、域内工具和来源读取分别验证精确动作与范围，覆盖新建、本人历史查看、PDF及重新生成。
- [ ] 4.3 用相同请求样例验证 Schema、领域入口和前端呈现，覆盖临时条件、建档客户权限、两套选择、旧版提醒、下架后不能重新生成及新旧报告同源引用。更新 LR-204 和对应缺陷的实施状态。
