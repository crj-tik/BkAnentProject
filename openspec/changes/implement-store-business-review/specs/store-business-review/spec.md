# 门店经营卡点复盘契约

## Purpose

面向知识运营人员与店长，把房源维护、带看和成交推进中的卡点变成有事实、假设、动作及观察记录的持续经营事项。初期用明确标记的模拟数据验证完整业务流程，并为后续真实数据接入保留一致口径、权限及来源边界。

## ADDED Requirements

### Requirement: 经营输入使用有来源的独立数据集

系统 SHALL 通过明确的数据契约读取带看、跟进、议价和维护事实，包含稳定来源、版本、事件/观察时间、dataset 及数据模式；房源只通过房源域公开接口引用，知识材料保留访谈来源链。模拟数据必须标记 SIMULATED，未知性质标记 UNKNOWN，包含不同性质证据的结果不得整体标为 REAL。

#### Scenario: 真实房源与模拟带看共同参与诊断
- **WHEN** 一次复盘使用真实接口房源和模拟带看记录
- **THEN** 诊断、计划、指标和导出标明 MIXED 并显示各来源模式，不能宣称基于全真实经营事实

### Requirement: 复盘事项绑定当前主体与门店范围

创建、查询、修改、确认和观察经营事项 SHALL 核验当前可信用户及门店/资源范围；请求中的 storeId、employeeId、ownerId 和 Agent 摘要不得授予权限。业务事项、执行任务与 Memory 事项身份 MUST 保持不同语义。

#### Scenario: 修改其他范围的推进事项
- **WHEN** 请求携带已知事项 ID 但当前主体没有其门店操作范围
- **THEN** 系统拒绝读取或修改正文，不因请求填写相同工号而通过

### Requirement: 卡点解释区分事实假设和资料缺口

复盘 SHALL 输出有出处的事实、原因假设、待核实问题和建议动作，并保留所采用的证据及知识 revision。缺少关键事实时 SHALL 明确缺口，模型不得生成不存在的带看、反馈、成交或因果结论。

#### Scenario: 仅有带看量且没有客户反馈
- **WHEN** 店长请求解释带看后未推进的原因
- **THEN** 系统说明缺少反馈依据，给出待核实问题及有条件假设，不直接断言价格、经纪人能力或客户意向是已确认原因

### Requirement: 知识和房源变化使旧计划待复核

计划确认和依赖内容使用前 SHALL 复核当前房源版本、知识发布状态及来源授权。依赖变化 MUST 将相关建议标为待复核或拒绝旧版本确认，已发生的执行事实仍可按权限查询。

#### Scenario: 确认前打法已被撤回
- **WHEN** 店长准备确认的计划引用了已撤回的打法 revision
- **THEN** 系统不接受该旧计划确认，不展示失效依赖正文，并保留原计划和已完成动作的审计身份

### Requirement: 推进动作由当前版本的明确确认产生

系统 SHALL 将计划内容、负责人、期限、证据/知识版本和实际参数 hash 绑定为不可变确认对象。确认必须具备当前权限及 expectedPlanVersion，相同请求幂等返回原回执，不同内容复用同号或旧确认批准新计划 MUST 拒绝。

#### Scenario: 确认响应丢失后重试
- **WHEN** 店长以相同 requestId 和相同计划版本重试确认
- **THEN** 系统找回原动作集合和回执，不重复创建任务

### Requirement: 动作完成与上游经营状态分别确认

动作 SHALL 记录提出、确认、执行中、完成或取消状态及操作者/时间/证据。仅人工反馈时 MUST 标记 USER_REPORTED，只有可核验对应来源回执才能标记 SOURCE_CONFIRMED；任务 DONE 不得自动宣称客户成交、房源调价或外部消息发送成功。

#### Scenario: 经纪人勾选已联系客户
- **WHEN** 动作只有操作人的完成反馈且无上游状态变化回执
- **THEN** 系统保存 USER_REPORTED 的动作完成，保持原客户/房源/成交事实，不增加来源确认的成交数量

### Requirement: 指标记录分母口径窗口及未知状态

经营指标 SHALL 记录定义版本、观察时间、时区、样本范围、聚合单位及分子/分母；效率观察与经营阶段结果分别表达。分母为零、事实缺失或来源不可用时 MUST 返回 UNKNOWN 和原因，前后差异不得自动成为因果增长证明。

#### Scenario: 当前窗口没有可用机会样本
- **WHEN** 有效下一步率的分母为零或反馈记录缺失
- **THEN** 系统返回 UNKNOWN 及明确原因，不显示零转化或凭建议动作数生成改善百分比

### Requirement: 模拟结果不发布真实效果证据

模拟或混合数据产生的复盘、动作及观察 SHALL 保留来源模式和 dataset 隔离，不能通过改标记迁入真实历史，也不得发布为生产 Memory 业务结果证明。模型自评、工具受理或人工勾选完成不构成受信经营结果。

#### Scenario: 模拟场景产生正向转化变化
- **WHEN** fixture 数据显示转化改善
- **THEN** 系统可以报告模拟流程观察，不能宣称真实门店业绩增长或将其写成生产有效经验的结果事件

### Requirement: 经营流程保留领域权威和通用 Agent 治理

经营状态 SHALL 由经营域保存并以稳定回执查询，Supervisor 仅协调已授权调用；首期通过领域 API 和安全结构化结果提供能力。官方经营 Agent MUST 保留必需 Memory、技能范围和调用审批，不能按诊断文字自动推进外部业务或增加固定领域路由。

#### Scenario: 建议包含调整价格和通知客户
- **WHEN** 模型提出这些后续动作但用户仅确认本期经营推进计划
- **THEN** 系统只建立范围内的推进记录，不自动修改上游价格或发送消息，也不把建议当作外部动作批准

### Requirement: 固定消费契约允许本域独立运行

经营域 SHALL 按 domain-parallel-v1 的公开 HTTP契约消费房源及已发布知识，提供显式选择的模拟来源与真实接口模式。模拟来源只替代远端读取并保留数据模式，本域诊断、计划、动作、回执和持久记录仍须实际执行。真实接口模式在未配置、未知版本、拒绝或依赖故障时 MUST 保持对应失败，不得回退模拟；生产 Auth/Memory 接线缺失也不得旁路。

#### Scenario: 房源与知识新服务尚未部署
- **WHEN** 经营域显式选择固定 v1 模拟来源，实际本域处理器/存储及受控测试身份可用，而房源/知识的新增实现尚不存在
- **THEN** 系统能完成模拟卡点诊断、确认、执行反馈和回执查询，所有输出保留模拟标记，不需要等待其它 change 或复制其业务实现

#### Scenario: 已选真实接口但不可连接
- **WHEN** 经营域已选择真实 HTTP来源且目标不可用
- **THEN** 系统返回结构化依赖不可用，不转成模拟建议成功、不伪造无匹配，也不将独立模拟验收记录标成真实互通证据
