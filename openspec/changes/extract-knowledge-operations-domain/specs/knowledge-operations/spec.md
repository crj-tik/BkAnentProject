# 经验知识运营契约

## Purpose

支持知识运营人员把获准访谈整理为可审核、发布、引用和撤回的经营案例与打法，向店长提供带来源、适用边界和版本的经营支持。将知识质量、应用证据和发布权限分别管理，保障个人记忆、访谈事实和运营知识的独立责任。

## ADDED Requirements

### Requirement: Supervisor 将知识准备与发布写操作分开

Supervisor 知识技能 SHALL 通过动态目录调用知识提炼、查询和审核准备能力；发布与撤回 MUST 是分别绑定 revision、范围和 expectedVersion 且可单独获用户批准的能力。一次调用审批仅授权该次工具调用，不能替代知识域要求的非提交者人工审核；A2A Agent 不得在未单独获批时内嵌发布或撤回。

#### Scenario: 知识草稿尚未通过审核
- **WHEN** Supervisor 请求发布未获非提交者审核通过的知识 revision
- **THEN** 系统拒绝发布且不创建 PUBLISHED revision，即使工具调用已获 Supervisor 批准

#### Scenario: Supervisor 发布调用被拒绝
- **WHEN** 知识 revision 已审核通过，但 Supervisor 的独立发布能力未获批准或被拒绝
- **THEN** 不执行发布工具，revision 保持原状态

#### Scenario: Supervisor 撤回调用未获批准
- **WHEN** Supervisor 的独立撤回能力未获批准或目标 revision/范围/expectedVersion 已变化
- **THEN** 不执行撤回，知识仍按当前有效 revision 与范围提供服务

#### Scenario: 撤回后检查下游引用
- **WHEN** Supervisor 对已发布知识调用获批撤回
- **THEN** 知识域保存撤回回执，下游 check 返回不可继续使用的状态且不再返回正文

### Requirement: 经营知识拥有独立身份及结构化边界

系统 SHALL 为运营案例和打法分配独立业务身份及不可变 revision，记录经营问题、情境、前提、动作、来源所述结果、适用边界、未核实项和证据引用。来源资产 ID、旧报告 ID 与新知识 ID MUST 保持不同语义。

#### Scenario: 同一来源产生两个运营版本
- **WHEN** 同一逐字稿的打法被运营人员修订
- **THEN** 系统创建可追溯的新 revision 并保留前版及来源，不覆盖访谈逐字稿或原报告

### Requirement: 原声与经营效果证据分别验证

原声引用 SHALL 对照精确来源快照核验；来源评级、案例成功叙述、模型质量分和重复样本数量 MUST NOT 单独成为已证实经营有效的依据。归纳 SHALL 保留出处、反例或缺失说明，并区分自述、已核验和未验证结果。

#### Scenario: 多个案例提到相同做法
- **WHEN** 两个或更多案例出现同一种做法但缺少独立效果证据
- **THEN** 系统可以形成有来源的候选归纳，不能仅按样本数量标记为已验证有效

### Requirement: 编辑审核与发布遵循当前权限和版本

知识 SHALL 提供草稿、待审核、已发布和已撤回状态，编辑创建新 revision，提交/审核/发布/撤回均核验当前操作权限和 expectedVersion，并记录实际操作者及决定。审核者 MUST 与提交者不同；组织策略可增加更严格要求，但不得允许自审。模型生成完成或 Supervisor 工具调用批准均不得替代人工发布决定。

#### Scenario: 两人并发修改或审核
- **WHEN** 一个请求基于旧 revision 提交审核或发布
- **THEN** 系统返回可辨识版本冲突，保留已接受的新修订和原回执，不覆盖后续内容

#### Scenario: 提交者尝试审核自己的 revision
- **WHEN** 当前审核请求主体与该 revision 的提交者相同
- **THEN** 系统拒绝审核或发布，保持待审核状态并记录拒绝原因

### Requirement: 操作回执和生成任务可可靠找回

生成、编辑及运营动作 SHALL 以稳定请求身份和内容 hash 幂等受理；相同请求返回原任务/回执，不同内容复用同号 MUST 拒绝。已经完成的生成结果不重新调用模型，结果未知时 SHALL 核对原任务而非创建替代执行。

#### Scenario: 发布已提交但响应丢失
- **WHEN** 调用者用相同 requestId 和相同版本内容重试
- **THEN** 系统返回原发布回执和实际状态，不新增第二次发布或丢失审核记录

### Requirement: 已发布知识使用当前范围和依赖检查

检索、详情、导出和 Agent 使用 SHALL 核验当前用户范围、目标 revision 状态及来源依赖。未发布、已撤回或无权访问的正文 MUST 不得进入匹配、摘要或诊断；没有实现的组织范围能力必须明确不可用。

#### Scenario: 用户知道另一门店的知识 ID
- **WHEN** 当前用户提供不在其可读范围内的知识 ID
- **THEN** 系统拒绝读取正文，不能按 ID 已存在或调用者是店长推定可见

### Requirement: 知识检索保持领域真源责任

系统 SHALL 支持按经营问题、场景、标签和关键词查询当前获准已发布知识，合法无匹配与来源/存储不可用分别表达。语义索引可作为派生能力，MUST NOT 替代知识域的最终状态和授权复核，也不得自行读取个人 Memory 以补充缺失正文。

#### Scenario: 检索未命中与服务故障
- **WHEN** 查询成功但没有可读知识，或依赖访问失败
- **THEN** 前者返回合法空结果，后者返回可辨识不可用，二者不会互相伪装

### Requirement: 领域知识发布与 Memory 共享保持独立

发布经营知识 SHALL 仅授予该知识契约允许的范围，不自动开放访谈私有会话、个人偏好历程或 Memory 共享经验。新官方知识 Agent MUST 使用必需 Memory 生命周期及精确注册身份，基础 Memory 失败时在模型/工具执行前拒绝。

#### Scenario: 知识 Agent 缺少 Memory 授权
- **WHEN** 官方知识 Agent 的基础工作集读取或当前范围核验失败
- **THEN** 本轮模型和业务工具均不执行，不能因知识服务可查询而走无记忆旁路

#### Scenario: 运营人员发布一个案例
- **WHEN** 知识案例审核发布完成
- **THEN** 系统保留知识发布回执，不自动生成个人偏好或跨用户 Memory 共享经验授权

### Requirement: 已发布知识通过冻结 v1 公开契约消费

知识域 SHALL 提供 domain-parallel-v1 的 published/search、published/batch-read 和 published/check 三个 POST 契约。包络、路径和字段遵循并行总览，知识引用包含 knowledgeId/revision/contentHash，快照保留发布状态、模式、dataset、来源引用及获准派生正文；不得返回私有逐字稿全文。check 只读区分当前、过时、不可访问及不可用，访问整体无效必须拒绝而非空匹配。

#### Scenario: 经营消费者尚未实施
- **WHEN** 本域已具备获准的模拟访谈来源和知识发布版本，但没有经营或房源的新增实现
- **THEN** 当前受权用户仍能通过固定知识 v1 契约查询、读取并检查该版本，不要求其它 change 提供新的 Java 类型或服务

#### Scenario: 知识版本撤回后的当前检查
- **WHEN** 调用者检查一个已撤回或失去当前访问权的知识引用
- **THEN** 返回 NOT_ACCESSIBLE 且不带正文；来源依赖故障返回 UNAVAILABLE，不能把二者解释成可继续使用

### Requirement: 知识运营域拥有案例与经营知识的完整生命周期

知识域 SHALL 提供知识案例/打法及共性候选的生成或创建、编辑、提交审核、非提交者审核、发布、精确版本检索和撤回能力，并保留获准逐字稿来源引用及证据状态。每项原知识运营能力 MUST 有统一域目标 API/技能/工具及调用方迁移记录；仅迁移占位表或只读检索不构成功能合并。

#### Scenario: 从已授权访谈材料运营一条打法
- **WHEN** 运营人员从获准逐字稿创建打法候选，编辑后由另一名有权人员审核并发布
- **THEN** 系统保存来源引用、内容 revision、审核与发布回执，当前用户可按权限检索精确发布版本

#### Scenario: 撤回已发布知识
- **WHEN** 获准人员撤回一条已发布打法或共性版本
- **THEN** 系统保留历史版本和审计引用，当前检索不再返回可用正文，消费者检查得到撤回状态

### Requirement: 抽取知识运营不得破坏访谈运行面

知识运营抽取 SHALL 保持访谈域作为会话、话轮、逐字稿及报告任务的权威。开案、会话交互、逐字稿提交/搜索/评级和报告生成/查询/搜索的既有业务结果 MUST 继续由 `interview-service` 目标入口提供，不因知识服务创建或数据映射而消失。

#### Scenario: 知识域启用后继续完成访谈
- **WHEN** 用户在知识服务启用后通过原访谈入口完成会话、提交逐字稿并查询报告任务
- **THEN** 访谈运行面保留原有结果和身份，知识服务仅消费经过授权的来源快照，不接管会话状态或报告权威
