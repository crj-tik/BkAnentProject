## 1. 客源归属与授权

- [ ] 1.1 在客户创建、列表、搜索和详情中统一负责人及管理员读取规则，服务端从可信身份生成新客源归属。
- [ ] 1.2 在匹配和产物读取应用同一客户范围，管理员身份、操作权限和资源范围共同校验。覆盖本人、同部门其他经纪人、无管理员身份却持有全量读取码、撤权和超范围管理。
- [ ] 1.3 按后续重复手机号决策定义登记行为与并发重试，保留现有负责人数据，历史归属依据原证据核对。

## 2. 匹配契约与来源

- [ ] 2.1 将动作请求/结果 Schema、任务完成和错误分支接入实际可执行入口及共用 A2A 契约。保持管理端当前字段的兼容读取。
- [ ] 2.2 核对客户为可用买方档案，按后续问答确定需求最低字段、区间合法性及硬软条件，明确客户预算与房源价格的单位换算。
- [ ] 2.3 复用 Listing 当前在售读取及结果复查，返回逐套理由、稳定引用和事实版本。覆盖下架、已成交、删除、撤权与旧缓存。

## 3. 完成状态与验收

- [ ] 3.1 验收有候选、成功零候选、输入不足、来源失败和无权操作，页面展示、任务查询、调用记录与完成事件一致。
- [ ] 3.2 验收修改客户需求后重新匹配，确认新旧结果对应各自的需求与来源事实。业务完成点为候选及理由交付。
- [ ] 3.3 盘点现有咨询、跟进和旧 RPC 入口的适用范围，确认真实能力目录与本期业务完成点一致，按需要更新设计及缺陷记录。
