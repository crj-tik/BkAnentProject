## 1. 客源归属与授权

- [ ] 1.1 在客户创建、列表、搜索和详情中统一买方角色负责人及管理员读取规则，服务端从可信身份生成新买方角色归属。
- [ ] 1.2 在匹配和产物读取应用同一客户范围，管理员身份、操作权限和资源范围共同校验。覆盖本人、同部门其他经纪人、无管理员身份却持有全量读取码、撤权和超范围管理。
- [ ] 1.3 首次登记强制提供身份证，以文档查重键确定唯一买方身份。重复登记返回身份已存在并拦住 B 新建，定位同一既有身份及业主档案。验收首次缺证件、同身份证并发登记、同请求重试、不同证件共用电话、旧档案读兼容，以及重复命中不改变原归属或扩大读取权。
- [ ] 1.4 核对经纪人手机号字段、登记与变更入口，按规范化号码执行唯一约束；业主联系电话可重复。涉及持久化的变更使用受管迁移。
- [ ] 1.5 按买方与业主角色共用方式补齐登记请求和结果 Schema，首次证件必填、身份已存在、同请求重放分别具有明确契约；给既有身份和业主引用执行资源授权。
- [ ] 1.6 受管迁移增加档案角色集合并从历史 `profile_type` 生成已有角色，保留旧字段和读取兼容。更新按角色查询、匹配、业主验证及 DTO，验收一个身份证同时买房卖房、原编号保持、追加角色不删除旧角色。
- [ ] 1.7 业主引用按房源用途独立鉴权，使不同经纪人负责的房源可关联同一档案。验收首次登记可验证引用、重复建档被阻止、受权引用成功、各房源归属独立，买方需求按其角色权限展示。
- [ ] 1.8 在原 `OWNER` 档案新增 `CUSTOMER` 角色并绑定当前经纪人。验收 A 建业主档案、B 新增买方角色后需求归 B，原房源和资料保留，已有买方角色不能通过重放或重复添加接管。
- [ ] 1.9 向关联房源负责人提供姓名、联系方式及其本人房源投影，支持任一关联负责人及授权管理员校正共享联系资料并审计。验收角色权限隔离、主表原负责人不能据此读取其他人负责的买方需求、无关联经纪人拒绝，以及并发校正不覆盖新版本。

## 2. 匹配契约与来源

- [ ] 2.1 将动作请求/结果 Schema、任务完成和错误分支接入实际可执行入口及共用 A2A 契约。保持管理端当前字段的兼容读取。
- [ ] 2.2 核对客户为可用买方档案，按区域、预算上限及明确房厅数量执行硬筛选。预算与区域缺失时通过 Supervisor 补问，有对话依据时提取并记录来源。明确金额换算、区间校验及结构化房厅映射。
- [ ] 2.3 复用 Listing 当前在售读取及结果复查，返回逐套理由、稳定引用和事实版本。覆盖下架、已成交、删除、撤权与旧缓存。
- [ ] 2.4 严格满足软偏好的候选优先，放宽候选随后并标明差异。验收超预算、跨区域、指定房厅不符的房源一律排除，以及完全匹配候选优先于分数更高的放宽候选。

## 3. 完成状态与验收

- [ ] 3.1 验收有候选、成功零候选、输入不足、来源失败和无权操作，页面展示、任务查询、调用记录与完成事件一致。
- [ ] 3.2 验收修改客户需求后重新匹配，确认新旧结果对应各自的需求与来源事实。业务完成点为候选及理由交付。
- [ ] 3.3 盘点现有咨询、跟进和旧 RPC 入口的适用范围，确认真实能力目录与本期业务完成点一致，按需要更新设计及缺陷记录。
