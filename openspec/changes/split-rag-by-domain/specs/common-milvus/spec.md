## Purpose

为需要 RAG 能力的各业务域提供共享的 Milvus 向量存储与 embedding 基础库：统一连接管理、集合初始化、文档 upsert/删除/检索抽象，使域服务（房源、记忆及未来接入的域）以一致的契约集成向量检索，避免各域重复维护基础设施代码。

## ADDED Requirements

### Requirement: 迁移复用现有向量存储行为

共享向量能力 SHALL 继续提供集合初始化、文档 upsert、按 ID 删除和向量检索，迁移后 MUST 保持原实现的输入输出与既有集合兼容，不因宿主变更而要求重建数据。各域 MUST 能复用同一基础设施封装，域内业务规则不由共享存储层决定。本次变更 MUST NOT 要求第二套存储实现作为接入条件。

#### Scenario: 记忆宿主复用原存储行为
- **WHEN** 记忆服务集成共享能力并使用与迁移前一致的配置
- **THEN** 原有记忆文档可继续检索和更新，不需要用另一实现重新建立向量

#### Scenario: 既有文档身份与来源兼容
- **WHEN** 迁移后读取或按 ID 删除迁移前写入的文档
- **THEN** 文档身份、来源、内容与元数据仍可正确解析，删除作用于原文档而不是另一套 ID 映射

### Requirement: embedding 客户端封装

共享能力 SHALL 复用原有 embedding 接入，继续通过配置的 OpenAI 兼容端点获得向量；写入与查询 MUST 使用一致的 embedding 模型与维度，维度与目标集合声明一致。本次迁移 MUST NOT 要求新增直接 HTTP embedding 客户端或改变既有存储写入/查询流程。

#### Scenario: 写入与检索维度一致
- **WHEN** 文档以维度 1024 写入集合后发起检索
- **THEN** 检索使用的 embedding 模型输出维度同为 1024，不因写入/查询模型不一致而产生错误

### Requirement: 连接与集合配置外置

common-milvus 的 Milvus 端点、凭据、集合字段映射（主键、向量、文本、元数据字段）、索引类型与维度 SHALL 全部由宿主服务的配置（Nacos data ID 环境变量）提供，模块本身 MUST NOT 内置端点地址或凭据默认值以外的硬编码。

#### Scenario: 各域独立配置
- **WHEN** 两个域服务分别引入 common-milvus 并配置各自的集合名
- **THEN** 两服务互不感知对方集合，配置错误互不传染

### Requirement: 不同集合组织不同域的内容

共享同一 Milvus 实例时，各域 SHALL 按明确配置的集合组织内容，文档 MUST 区分集合命名约定与调用者访问授权。集合命名 MUST NOT 被当作域或用户权限检查的替代。服务端访问范围与身份过滤仍由域服务负责。

#### Scenario: 查询目标集合的内容范围
- **WHEN** 对 `listing_knowledge` 集合发起获准的查询
- **THEN** 结果只来自该集合，其他集合的文档不自动合并到结果；这不表示调用者因此获准访问其他集合
