## ADDED Requirements

### Requirement: 受监督领域委托的版本化 A2A 业务契约

受监督业务的 A2A 委托 MUST 使用官方消息、任务和产物承载统一版本的结构化信封。平台 SHALL 按已登记的目标、动作与契约版本校验入参和返回，关联任务、消息、调用与因果关系，并验证服务身份、现行权限及有效技能范围。目标领域需要其他域的能力时 MUST 通过 Supervisor 提交结构化依赖。Supervisor SHALL 对后续委托单独治理并把结果关联回原领域。模型可继续根据结果做业务决策，领域依赖本身不得授权或绕过治理。

#### Scenario: 营销依赖当前房源

- **WHEN** 营销 Agent 在草稿环节返回已登记的 Listing 快照依赖
- **THEN** Supervisor 按同一信封校验并治理该依赖，关联请求、房源子任务、结果和原营销任务，再恢复原营销任务

#### Scenario: 跨域契约或权限校验失败

- **WHEN** 消息的信封版本、动作、数据或调用范围校验失败
- **THEN** 系统保存可关联的结构化错误；目标业务操作不执行，原流程不会把无效输入或输出当作已通过的领域事实

### Requirement: 领域任务以 Supervisor 作为人工处理入口

受监督领域 Agent 请求人工处理时 MUST 返回待办类型、目标资源及版本、允许决策与显示所需的结构化数据。Supervisor MUST 保存待办、原领域 Task 与关联版本，提供按动作授权的页面、决策和恢复。仅符合当前业务动作及资源范围的人员可见和处理对应待办，部门代办权限不得转移原任务所有权。恢复 MUST 拒绝过期版本、未授权或不在允许列表中的选项，去重重复决策，并以签名身份恢复原领域等待。领域 MUST 验证业务版本和动作授权。

#### Scenario: 原任务等待领域人工审批

- **WHEN** 领域 Agent 请求草稿审核或发布确认
- **THEN** 原任务持久化为等待人工，页面显示对应内容和版本，异步状态与 SSE 都不会将等待报告为已办结

#### Scenario: 同部门管理员代办

- **WHEN** 原发布任务的业务规则允许本部门发布管理员处理指定动作，且其权限与资源范围当前有效
- **THEN** Supervisor 允许该管理员查看并提交对应决策，记录其实际身份，原任务归属仍可追溯

#### Scenario: 原确认已失效或重复提交

- **WHEN** 浏览器重复提交同一决定，或针对已经替换的版本提交确认
- **THEN** 重复提交返回现有处理结果，过期版本要求再次打开当前待办，两种情况都不会新增未批准的执行

#### Scenario: 登录恢复与发布授权是独立决策

- **WHEN** 部门渠道账号恢复登录
- **THEN** Supervisor 恢复原发布确认页面，只有符合确认资格的人员再次点击才能获得一次发布执行授权
