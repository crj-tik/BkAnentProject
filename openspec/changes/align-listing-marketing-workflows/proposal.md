## Why

房源现在可以由经纪人从待上架或已下架直接改成在售，缺少管理员对本次上架申请的真实性审核记录。营销已有草稿和发布计划，但草稿版本、房源事实、两次人工确认和实际发布回执没有在 Supervisor 的同一任务内贯通。

## What Changes

- 经纪人代业主登记、提交房源并负责持续跟踪。首次上架和每次重新上架都需由管理员审核本次申请的资料真实性，通过后执行上架。退回时保留理由，由经纪人修改后重提。
- 在售房源下架后回到经纪人的「已登记」，保留原房源草稿。再次点击上架时，比对本次下架时的业主关联和基础资料。基础资料变化逐项提示。业主变化且尚未办理换绑时拦截申请。真实业主已更换的，经纪人在原房源上办理业主变更，沿用原编号和已有资料，换绑完成后可另行申请上架。
- 一期审核校验业主关联与基础展示字段，保留已有产权、委托、合同、OCR 和核验资料字段。负责经纪人直接维护挂牌价，保存原价、新价、操作者和时间。
- 在售房源的地址、户型、面积、挂牌价、描述及素材等资料可由负责经纪人按现有权限直接校正。校正后继续在售并留存资料版本和变更记录。业主关联调整使用独立的业主变更流程。
- 在售房源更换业主时，先下架并保存原资料，再在原房源换绑业主，随后重新申请上架，由管理员审核通过后恢复在售。
- 下游始终只使用在售房源。未上架房源仅在房源管理入口对负责人和有明确权限的管理员可见。
- 同一个营销 Agent 完成草稿、内容自审、发布准备和执行。草稿确认前检查房源状态与调价，确认后按冻结的草稿和素材准备发布。发布另需人工确认具体计划。
- 受监督流程中的人工暂停和恢复由 Supervisor 负责。领域 Agent 通过官方 A2A 载体交换统一版本契约，领域之间经 Supervisor 回转，按业务动作校验各自数据。营销 Agent 调用本域注册的发布工具，由工具适配器委托小红书 MCP。
- 小红书使用部门账号。登录恢复后回到发布确认页，人工再次点击才执行。MCP 返回明确成功即可办结，原确认人或相应部门发布管理员发现未刊登时可记录人工结果并发起新的受确认发布尝试。

## Capabilities

### New Capabilities

- `marketing-supervised-release` 定义同一营销任务从草稿到人工重发的业务规则。

### Modified Capabilities

- `listing-internal-management` 增加每次上架申请的真实性审核，明确价格维护与不同房源读取用途的边界。
- `supervisor-tool-orchestration` 增加结构化领域回转和领域人工节点的审批、授权、续接规范。

## Impact

- `listing-master-service`、`customer-service` 和 `auth-service` 提供房源、业主档案及可信角色和资源范围。房源审核与上架由房源域落库。
- `agent-service`、共享 A2A 契约、Studio 人工审批呈现与运行记录需要联动。
- `marketing-content-service` 复用营销 Campaign 生命周期、领域 Agent 和 MCP 注册边界，并接入部门小红书 MCP。旧版兼容入口只能在适用时走同一业务约束。
- 本提案覆盖已经明确的房源和营销规则。共享契约供后续领域复用，各领域的业务动作和验收条件逐域确认。已有房源在售门槛见 KI-290，其余改动按任务清单实施。
