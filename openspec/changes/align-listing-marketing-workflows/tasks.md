## 1. 共享契约与 Supervisor

- [ ] 1.1 在共享模块发布共同 A2A 信封、动作及审批视图登记和样例。验收请求、结果、续接的正反例，并将输入和输出都纳入动作版本校验。
- [ ] 1.2 在 `agent-service` 识别领域待办和跨域依赖，持久化原子任务、对应动作和版本、依赖与审批关联。在官方 A2A 下传递结构化数据和最小签名权限。
- [ ] 1.3 复用 Supervisor 审批节点增加合约化领域待办，接入 Studio 查询、决定和 SSE。验收按权限代办、撤权、过期审批、重复回调、恢复原任务及等待/失败事件语义（KI-283）。

## 2. 房源真实性审核与维护

- [ ] 2.1 在 Listing 受管迁移新增上架申请和真实性审核记录，以申请编号关联送审版本、决定和上架流水，区分首次与重新申请。复用 Customer 业主类型/范围校验和 Auth 负责人、审核管理员授权。保留原房源、证件、委托、合同、OCR 和核验字段。
- [ ] 2.2 将首次与重新申请接入同一管理员审核入口。所有上架执行入口校验本次申请、管理员授权及送审版本。验收资料无变化的重新上架、换绑后重新上架、旧批准重放、重复提交、并发修改、退回重提和老在售记录。对每种申请检查待审时下游不可选、批准并上架后可选。
- [ ] 2.3 确认现有经纪人调价提交和索引事件的一致性。验收经纪人改价无需审批、新旧价与操作人可追溯、过期版本不覆盖和金额单位一致。
- [ ] 2.4 在 listing-agent 注册 `listing.snapshot.read`，复用权威来源检查和 KI-290 的在售门槛。验收不同访问用途、房源下架、无权限、数据源异常和金额精度。
- [ ] 2.5 在下架事务中按状态流水保存业主档案 ID 和基础资料快照。经纪人在「已登记」继续编辑原房源。验收下架后退出在售候选、快照与当前草稿独立、重复下架请求、多个上下架周期和存量缺少快照的提示。
- [ ] 2.6 为再次上架预检与申请定义管理接口输入、结果分支和字段差异 Schema。所有申请入口复用服务端比对。验收资料一致、仅基础资料变化、业主变化未办理或解除关联、业主和基础资料同时变化，以及预览后又改资料。
- [ ] 2.7 在原房源的业主关联入口接入下架期间换绑，校验负责经纪人及新业主档案，原子记录前后关联。验收房源 ID 与基础资料保留、下架快照可查原业主、换绑本身不提交上架、经纪人再次申请可使用新业主，以及旧换绑记录无法放行新差异。

## 3. 营销草稿确认

- [ ] 3.1 将 `marketing-agent` 的结构化草稿入口接入同一 Campaign 工作流。保存正文、素材版本和来源快照。由领域发出待审动作，在 Supervisor 展示给发起人。
- [ ] 3.2 接入草稿退回意见、原任务改稿、房源替换及确认前的 A2A 复查。验收价格更新、知情沿用及提醒审计、房源不再可选、来源不可用、等待期间再次调价和过时的批准。
- [ ] 3.3 在营销域保存审核目标、决定、素材摘要和事实快照，发布准备只消费已审 revision。验收草稿审批后调价或下架不触发房源查询，改用其他正文或素材需要新的审核。

## 4. 发布、登录与人工重发

- [ ] 4.1 在 `marketing-content-service` 注册本域发布工具。通过小红书 MCP 接入部门账号可用性、登录二维码和实际发布结果适配，固定目标账号的身份与渠道配置。Supervisor 通过 A2A 进营销 Agent。
- [ ] 4.2 在 Supervisor 展示冻结的发布计划，接入明确的人为发布动作。验收审核通过未点击、计划过期、其他部门、扫码登录恢复及原确认人再次点击。核对兼容入口均执行等效约束。
- [ ] 4.3 演进计划与请求的存储关系并添加可追溯的尝试、人工复核和新旧尝试关联。验收明确成功办结、超时保留未知、原确认人或部门发布管理员登记未刊登并再次确认重发、重复点击去重。
- [ ] 4.4 通过受控的渠道替身完成端到端验收。实际渠道调用的验收使用已授权的部门测试账号，并由现场确认人明确点击发布，核对返回结果和人工复核入口。

- [ ] 5.2 验证迁移、重启、回退及历史记录读取。确认现有数据和入口的兼容策略，更新 LR-197 及相关缺陷条目的实现状态。
