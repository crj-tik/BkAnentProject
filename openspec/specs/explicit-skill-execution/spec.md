# explicit-skill-execution Specification

## Purpose

为 Supervisor 提供请求级显式技能和模型自主技能加载，使模型在理解原始需求的同时遵循技能正文，并将正文与能力范围固定到本次任务及恢复过程；平台严格治理调用，但不提供业务步骤顺序保证。

## Requirements

### Requirement: 显式技能在首轮模型前加载

请求 SHALL 支持可选 skill 名称和版本；未指定时为 AUTO，指定有效技能时为 EXPLICIT_SKILL。系统 MUST 在首轮模型调用前验证归属、发布版本和能力策略，保存正文及范围快照，并向模型提供完整正文、原始请求及有效工具。指定技能只免去技能选择，MUST NOT 绕过模型的意图理解、参数提取、信息缺失和冲突处理。

#### Scenario: 指定技能后理解本次需求
- **WHEN** 用户指定找房、对比和营销指引，并用自然语言描述预算、地段和目标人群
- **THEN** 首轮模型获得正文和原始需求，在同一工具循环内提取参数并决定调用，不由平台预填一条固定业务执行计划

#### Scenario: 请求信息不足或与技能冲突
- **WHEN** 原始需求缺少必要业务信息，或模型识别出与指定技能不相容的目标
- **THEN** 模型可以追问或说明冲突，不因 skill 参数存在而直接执行全部正文过程

#### Scenario: 指定 skill 无效
- **WHEN** 请求指定未发布名称、非法归属、不存在版本或无效能力策略
- **THEN** 业务调用前返回具体技能错误，不切回默认 Agent、另一技能或无约束模式

### Requirement: AUTO 按目录摘要自主加载普通技能

AUTO SHALL 向模型提供允许自主加载的普通技能名称和 description，由模型决定是否调用技能加载能力。系统 MUST 在加载成功后保存正文与版本、记录模型选择来源并在下一轮提供正文和有效工具；失败加载 MUST NOT 激活尝试选择的技能。消息关键词或知识匹配 MUST NOT 强制选择技能或 Agent。

#### Scenario: 模型主动加载普通指引
- **WHEN** AUTO 中模型根据目录 description 请求一个允许自主加载的普通技能，加载成功
- **THEN** 后续轮次获得该正文与有效工具，选择来源记录为模型，执行仍由同一模型工具循环推进

#### Scenario: 技能加载失败
- **WHEN** 模型请求的技能不存在或加载失败
- **THEN** 模型收到关联错误结果，原有效技能状态不变，不以失败调用名称激活正文或范围

### Requirement: 跨服务过程指引首版要求显式选择

知识技能 SHALL 仅提供背景。首版承载跨服务固定过程指引的 Supervisor skill MUST 只允许本次请求显式选择；普通专项指引可以在 AUTO 由模型主动加载。目录、加载入口和执行校验 MUST 共同遵守发布限制，不能只隐藏目录项而允许猜名激活。两类执行技能 MUST 使用相同正文格式和模型循环，不引入 workflow 模式或独立执行器。

#### Scenario: AUTO 猜测受限技能名称
- **WHEN** AUTO 的模型请求加载一个只允许显式选择的跨服务过程技能
- **THEN** 加载被拒绝并返回选择方式错误，该技能不成为当前有效技能

#### Scenario: 用户显式选择跨服务过程指引
- **WHEN** 用户本次指定一个已发布且有效的跨服务过程技能
- **THEN** 平台首轮前加载其正文和范围，模型仍负责理解需求并逐轮选择能力

#### Scenario: 知识提示不强制路由
- **WHEN** 行业知识技能因背景匹配进入上下文
- **THEN** 不据此激活过程技能或预先调用某个领域 Agent

### Requirement: 正文过程是模型指引而非强制步骤

技能 SHALL 保持 frontmatter 与 Markdown 正文，其中调用对象、顺序、条件和结果使用方式由模型解释及遵循。系统 MUST NOT 将正文转换为业务步骤调度、DAG 或顺序、依赖、完成条件校验。范围内的有效调用 MUST NOT 仅因不符合正文顺序被程序拒绝；模型结束 MUST NOT 因遗漏正文业务步骤而被步骤检查器拦截。通用待调用、待审批和预算状态仍 MUST 正确处理。

#### Scenario: 调用顺序偏离正文
- **WHEN** 模型提出范围内且参数、权限、审批均有效的调用，但其顺序不同于正文指引
- **THEN** 平台不因业务顺序拒绝、不自动补前置步骤，运行轨迹可用于评估模型遵循偏差

#### Scenario: 模型提前结束正文流程
- **WHEN** 模型提出最终回答，没有待调用或待审批，但尚未调用正文描述的全部业务过程
- **THEN** 不执行技能步骤完成检查，也不自动补调用；评估能够记录遗漏，但不能据此宣称强制顺序保证

### Requirement: 技能能力范围在模型和执行端同时生效

显式技能 MUST 声明非空允许清单或明确继承本次授权能力的策略。解析、授权和请求选项校验 MUST 在业务调用前完成；解析失败、能力缺失或有效交集为空 MUST 返回错误，不能回退全量。模型可见工具与实际执行边界 MUST 遵守同一有效范围，显式选择不能被历史激活、旧 hint 或后续技能换名、换版本扩大。该限制只治理能力集合，MUST NOT 变成业务步骤校验。

#### Scenario: 显式选择后尝试换技能或越界
- **WHEN** 模型尝试加载另一个技能或调用允许清单之外的工具
- **THEN** 返回明确错误，原正文、版本和范围继续有效，不扩大能力集合

#### Scenario: 范围无法解析
- **WHEN** 显式技能的允许能力不存在、无权限或有效集合为空
- **THEN** 业务执行前拒绝技能选择，不开放全量工具或替换为默认 Agent

#### Scenario: 技能引用被禁用的 MCP
- **WHEN** 显式技能允许清单引用 MCP，但本次请求禁止 MCP
- **THEN** 返回能力策略冲突，不以技能覆盖请求限制或悄悄删掉该引用后执行

### Requirement: 技能版本与作用域固定到本次执行

系统 SHALL 在接受显式任务或模型成功加载技能时解析并保存正文、归属、版本、内容身份及有效范围快照；热更新只影响新加载或新任务，恢复 MUST 使用原快照。显式选择 SHALL 只作用于本次任务或明确续接任务，同会话新请求 MUST NOT 从历史消息继承旧显式选择；有效补充输入续接 MUST 保留原技能快照。普通 AUTO 技能切换 SHALL 始终受请求授权和当前有效范围约束。

#### Scenario: 热更新后恢复
- **WHEN** 暂停任务的技能内容更新后原任务恢复
- **THEN** 原任务继续使用原正文和能力快照，新任务可以使用新发布版本

#### Scenario: 新请求不继承旧显式技能
- **WHEN** 同会话结束显式技能任务后提交不携带 skill 和续接关联的新请求
- **THEN** 新请求进入 AUTO，历史激活不使其继续使用旧 explicit 策略

#### Scenario: 补充输入沿用原技能
- **WHEN** 等待输入的显式任务收到有效 owner 续接和缺失参数
- **THEN** 继续原任务、session、模式和快照，保留原请求能力政策与累计预算并重验当前权限，新增信息交给模型，不重新解析最新正文或换成另一技能

### Requirement: 技能加载与业务调用共享治理和恢复

技能加载结果和有效快照 SHALL 与 toolCallId、模型消息、审批、业务调用结果及产物关联持久化。平台身份、权限、预算和审批 MUST 优先于技能正文。恢复 MUST 复用已完成调用结果，不记录或推进技能业务步骤状态机；审批待办 MUST 以任务最新 checkpoint 状态判定。

#### Scenario: 技能未写审批但工具要求审批
- **WHEN** 技能执行中的工具动作属于平台要求审批的动作
- **THEN** 真实执行前暂停并等待有效批准，不能以技能正文代替批准

#### Scenario: 技能加载成功后进程重启
- **WHEN** 技能正文、版本和加载结果已持久化，下一轮模型调用前进程重启
- **THEN** 恢复使用相同快照和原加载调用结果，不按技能名称重新取最新版本，也不自动执行正文下一步骤
