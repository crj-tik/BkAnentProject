# Auth 与组织管理前端需求

适用范围：后续新建管理前端时纳入需求单。本仓库当前没有前端工程；本清单只定义需要对接的能力，不表示浏览器实现或验收已完成。后端保持最终授权权威，前端权限控制仅用于界面显示。

## 登录与会话

- 登录、refresh、logout，并正确处理一次性 refresh token 轮换；新 refresh token 必须原子替换旧值。并发多个 401 时只允许一个 refresh 请求，其余请求等待结果，避免重复轮换使会话失效。
- 所有受保护请求附带 Bearer access token；token、密码、签名上下文不得写入 URL、日志、分析事件、prompt、Memory 或用户可见错误消息。
- access token 过期时最多自动 refresh 一次；refresh 失败清理会话并跳转登录。401、403、409、429、5xx 应区分展示并提供适当恢复操作，不能无条件重试有副作用的请求。
- 优先使用短期 access token 与安全 HttpOnly/SameSite refresh cookie。当前后端登录/刷新契约仍在 JSON 中返回两种 token；正式前端定稿前需确认浏览器凭据存储与 CSRF 策略，不可默认为 localStorage 安全。
- logout 后清理前端会话；页面刷新、多个标签页、网络恢复和 refresh 并发均需验证。

## 本人档案与授权状态

- `GET /auth/me` 获取真实 userId、displayName、有效角色集合、管理员兼容投影、permissionRevision、credentialEpoch 和当前有效组织摘要；不能从旧单角色字段推导最终权限。
- `PATCH /auth/me/profile` 只允许修改 displayName。不得把 userId、角色、组织、账号状态、brokerId 或 storeId 放进本人资料表单。
- 当前用户界面可展示角色和组织信息；`businessAdmin` 只用于兼容显示，不可代替后端授权，也不能因为它为 true 就忽略具体权限错误。

## 用户、角色与权限管理

- 用户列表需支持分页、关键词和有效角色筛选；新增、编辑、停用、删除、密码重置均呈现后端确认结果，并按 409 冲突刷新数据。
- 允许一个用户绑定多个显式角色；展示角色类别（`JOB`、`MANAGEMENT`、`UNCLASSIFIED`）、有效起止时间和状态。不得因部门、岗位文本、模型输出或前端选择的身份字段自动授予角色。
- 角色维护使用 Auth 权限目录中已登记的精确权限码；基础通用操作不创建权限点，受限业务操作按后端登记的代码管理。前端只显示有权限使用的入口，所有服务端仍独立验证权限和资源归属。
- 管理员权限授予/撤销、最后管理员保护和旧 businessAdmin 迁移属于高风险管理动作，界面须展示目标用户、影响权限、确认步骤和失败原因；不能把一次迁移开关放进普通日常设置页。
- broker 身份、store 映射分别作为受控业务关联展示，与用户主键分开标注。不得让普通用户编辑，也不得以相同数字自动关联。

## 组织与成员管理

- 展示公司 → 门店/部门层级、节点类型/状态、门店业务 ID 显式映射及 revision。
- 支持受权管理员创建组织节点、启停节点、设置门店业务 ID、查看成员、添加成员、结束成员和同公司调动。
- 成员表单应展示 primary/secondary、`validFrom`/`validUntil`、当前是否有效；避免同一用户的主归属时间重叠。future-effective 变更需明确展示生效时间。
- 门店访问范围只显示已验证的 primary 有效门店映射；部门或 secondary 关系不显示为门店权限。禁用/移除映射被后端拒绝时，保留页面状态并展示待解决的成员或旧映射冲突。
- 用户列表、组织列表、成员列表在成功变更后刷新。以 permissionRevision/授权版本提示当前会话需要重新读取权限；不在前端自行延长签名上下文的有效期。

## Agent 对话与流式交互

- 以当前登录会话调用 Agent/Gateway API，并展示运行中、完成、待审批、待补充、失败和可重试状态；fetch/SSE 断线后先重新读取权威任务状态，再决定是否续订。
- 前端不提供 userId、brokerId、storeId 或 recipientUserId 作为身份来源，不允许从聊天内容中解析后覆盖身份；需要查询对象的业务 ID 只能作为资源选择参数，由服务端按签名 actor 和资源归属再次校验。
- Graph/subAgent 的请求上下文由 Gateway/Auth/Agent 后端绑定。浏览器只携带正常会话凭据及必要业务参数，不构造或修改签名授权上下文、run/session 绑定或权限列表。
- SSE/fetch 使用真实 Authorization header；重连、refresh、logout 后撤销、tab 切换和用户输入可疑身份字段应有浏览器级验收。

## 前端验收清单

- 登录错误、refresh 轮换、并发 refresh、401 单次恢复、logout 与撤销后拒绝。
- 多角色、角色有效期、权限目录展示、组织成员多关系与生效边界。
- 无权用户看不到管理入口，直接构造请求仍由后端拒绝；非管理员不得修改角色/组织/状态。
- 自有资源可读、其他用户资源被拒绝；伪造 userId/brokerId/storeId 不改变 actor。
- Agent SSE 正常/断线恢复，重复提交不重复产生副作用，权限过期或撤销后不能靠前端重试绕过。
- 浏览器不在 URL、持久化、日志、prompt、Memory 或诊断上报中泄露凭据和签名上下文。

后端 API 可用时先以 API 测试替代前端联调；上述浏览器专属行为待前端工程创建后单独验收。
